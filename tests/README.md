# dv-generate tests

Run everything offline: `tests/run.sh`
Run with the live import/export round trip: `tests/run.sh https://<your-dev-org>.crm.dynamics.com/` (needs `pac` authenticated to that environment).

**Use a throwaway dev environment.** Live mode imports unmanaged solutions `DvgenTest` and `DvgenFull` (publisher prefix `dvgen`) and leaves them installed.

| Step | What it checks | Needs Dataverse |
|---|---|---|
| 1 | `fixtures/DvgenFull` is exactly what `gen_full.py` produces from the SKILL.md templates | no |
| 2 | Every fixture XML file is well-formed | no |
| 3 | `lint.py`: the gotchas in SKILL.md (unmanaged only, prefix rules, element order, view wrapper, boolean structure, AppModule rules, env vars, connection references, GUID uniqueness) | no |
| 4 | `test_lint_mutations.py`: breaks the fixture 25 ways, one gotcha at a time, and requires lint to catch each | no |
| 5 | `pack.sh` produces a zip with the right root layout | no |
| 6 | `pac solution unpack` (SolutionPackager) accepts the packed fixtures | pac only |
| 7 | Import twice (second import is an overwrite), export, compare with `verify_export.py`, then export as managed | yes |

## What each fixture covers
- **DvgenFull**: 2 tables; text, multiline, decimal, integer, date, datetime, picklist and boolean columns; list and Quick Find views; main form using every control classid; AppModule + SiteMap. Generated by `gen_full.py`; edit the generator, not the XML, then re-run step 1.
- **DvgenTest**: 1 table, 5 environment variables (Text, Decimal, Boolean, JSON, Secret) and a connection reference. Hand-maintained.

## Regeneration matrix (`tests/regen/`)
`python3 tests/regen/run_regen.py <source-url> <target-url> [code ...]` runs 16 change scenarios (add/remove column, option, view, table, env var, connection reference, app; change label, type, default; plain update) against **two** dev environments: an unmanaged source and a managed target. Each scenario has its own publisher prefix (`dvg` + a letter code), so nothing needs resetting between scenarios, and takes about 5 to 8 minutes. `python3 tests/regen/summarize.py` prints what each path (dev overwrite, dev after solution-wrapper reset, managed upgrade) actually did against the regenerated spec. Results are in `tests/regen/results/`. The observation layer asserts nothing, and the target check cannot read picklist option values. Imports that remove a picklist option hung on 2 of 4 early attempts (15 minute timeout) and on 0 of 5 later timed trials, so scenario `ae` can still occasionally stall; treat a timeout as a retry, not a result.

`tests/test_drift.py` (part of `run.sh`, offline) checks `skills/dv-generate/scripts/drift.py` against the same 16 scenarios without needing an environment.

## Not covered
Lookups/relationships, security roles, web resources, `environmentvariablevalue`, deployment settings files, newer platform versions, and the older `26044.164` version strings used by DvgenFull (accepted by the environment under test).

## Cleaning up the dev environment
`pac solution delete` removes only the unmanaged solution wrapper. To remove the components, open make.powerapps.com → Solutions → the solution, delete the tables (`dvgen_widget`, `dvgen_project`, `dvgen_task`), environment variables, connection reference and app, then delete the solution.
